# Контракт первого production-релиза

Дата: 2026-10-04. План: `production-plan-100.md`.

## Обязательный результат

Публичный Next.js-каталог на reporadars.com с английскими маршрутами без префикса
и русскими `/ru`. Поиск, карточка скилла, коллекции и журнал используют
опубликованные редакционные данные. Сохранения и профиль остаются локальными
для браузера. Интерфейс сохраняет общий wordmark и палитру; тексты короткие,
шрифты DM Sans и Golos Text.

Владелец входит по настоящему письму. Админка позволяет публиковать, редактировать
и архивировать записи, проверять кандидатов, управлять источниками и наблюдать
запуски. Конкурирующие изменения требуют новой проверки редактором.

Импортер обнаруживает публичные GitHub-репозитории, сборники SKILL.md и готовые
пакеты Releases/Actions. Он сохраняет репозиторий, путь, commit, asset/run и хеши.
Неподтверждённое происхождение сборки показывается явно. Скачанный код не
исполняется. Первые источники работают в режиме ручной проверки; доверие и права
использования подтверждает владелец отдельно для каждого источника.

## Что разрешено отложить

Генерация и перевод описаний моделью, платные функции, облачная синхронизация
профиля, OAuth-провайдеры и исполнение скиллов не являются условиями выпуска.
Отсутствующий модельный адаптер не препятствует импорту исходных метаданных.

## Состояния и границы данных

- Редакционная запись: draft → published → archived; публикация проверяет поля
  и уникальный slug. Изменения имеют revision и аудит.
- Кандидат: needs_review, blocked, rejected, published. Заблокированный кандидат
  не публикуется кнопкой. Новый commit проходит новую проверку.
- Задача импортера: lease, завершение, пропуск, блокировка или повторная попытка.
  Ключ источника/версии предотвращает повторную обработку.
- Редакционная/auth SQLite, intake SQLite и jobs SQLite имеют разных владельцев
  и назначение. Публикация между базами имеет идемпотентную квитанцию.
- Публичная проекция содержит только опубликованный контент и публичное
  происхождение. Сессии, actor IDs, токены и signed download URLs в неё не входят.

## Доступ

Посетитель читает публичный каталог. Пользователь входит и управляет локальным
кабинетом. В первом выпуске редакционные изменения и управление источниками
доступны пользователю с активным административным grant. Отдельная роль editor
пока не реализована и не требуется для первого выпуска.
Служебный токен импортера принимает отчёты, но не создаёт человеческие сессии
и не заменяет подтверждение владельца. Владелец проекта отвечает за источники,
права использования и итоговый выпуск; автоматический обработчик выполняет
плановые задачи. Контакт для аварийных уведомлений ещё должен быть указан.

## Проверяемые критерии

Ноль открытых блокирующих ошибок в основных сценариях. Сборки static/runtime,
Node-, Go- и браузерные проверки проходят для того же пакета, который выпускается.
На staging проверены возврат релиза без отката рабочих данных и восстановление
копии в отдельный каталог. Публичные EN/RU URL, вход и доступ в админку проверены
после переключения Worker.

Начальные цели нагрузки: 20 параллельных читателей, p95 API до 500 мс и p95
прогретого HTML до 1 с на выбранном стенде. Это цели, а не результаты измерений.
Длительность автономного staging-прогона — 72 часа; наблюдение после открытия —
7 дней. Внешний пилот предполагает 3–5 согласованных участников. Эти проверки
завершаются по фактическим наблюдениям, а не автоматически при сборке.

## Управление импортом

Планировщик проверяет состояние каждую минуту; обычный импорт выполняется с
интервалом 24 часа, изменяемым в админке в пределах 6–168 часов. Редактор может
поставить один ограниченный запуск в очередь. Повторный запрос возвращает ту же
задачу, после завершения действует ограничение 15 минут между запросами.
Пауза блокирует импорт и автоматическую публикацию. Отдельное разрешение
автопубликации управляется для каждого источника; ручная редакционная работа
остаётся доступной во время паузы. Web-процесс не запускает привилегированный shell.

Варианты URL одного GitHub-репозитория объединяются без смены первого публичного
ID. Новый путь и зеркальный пакет требуют проверки редактора. Опубликованное
зеркало с тем же bundle SHA не объединяется автоматически; редактор может
архивировать прежнюю запись и опубликовать новую. Архивированная карточка
возвращает 404; автоматического переноса доверия и перенаправления нет.

Локальный SHA-256 подтверждает скачанные байты. Commit Release tag или Actions
run сохраняется как заявленное происхождение пакета и не считается аттестацией
его содержимого. Учётные данные GitHub не передаются на storage-host сборки.

Необходимые внешние данные: авторизация Cloudflare, права чтения Actions для
выбранных источников, подтверждение входа владельца и контакт уведомлений.
Git commit/push в текущую задачу не включены без отдельного указания пользователя.
