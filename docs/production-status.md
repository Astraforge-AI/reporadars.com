## Реализованный контур

- Next.js, короткие тексты, читаемые локальные шрифты, общий wordmark и EN/RU.
- Редакционная админка: публикация, изменения, архив, коллекции и статьи.
- Поиск по всей базе, пагинация, сохранения, sitemap и публичное происхождение.
- Обнаружение GitHub-источников и сборников; ZIP, `.skill`, tar.gz/tgz и Actions artifacts.
- Очередь с восстановлением, cooldown, проверками архивов и ручным рассмотрением.
- Расписание, пауза, ограниченный запуск из админки и журнал запусков.
- Отдельные UID/секреты, полные backups, проверенное восстановление и возврат релиза.

На финальном staging ручной запуск из админки завершил 3 импорта без ошибок.

Actions проверены fixtures; реальная authenticated загрузка ещё не подтверждена.
Автопубликация источника требует отдельного разрешения и подтверждения прав.
Импортер не исполняет скачанный код. LLM выключен для первого выпуска.

## Проверки и ограничения

`make verify`: 89 Node-тестов (включая 4 Sites), 74 браузерных сценария, 2 Python-теста,
Go race/vet, static и runtime builds. Проверены выбранные страницы axe и клавиатурой.
В финальном origin проходят восемь HTTP-проверок и SHA-256 всех 19 legacy assets.
Next.js пересобран из копии релиза; бинарник Go воспроизведён побайтно.

На нагрузочном стенде с 2005 fixtures: 20 параллельных читателей, 120 запросов,
0 ошибок; API p95 281 мс, EN/RU HTML p95 328/320 мс. Это ограниченный замер,
а не 72-часовой прогон и не замер публичной цепочки Cloudflare.

Npm audit: 0 уязвимостей. Semgrep: 0 находок в выбранных путях. React Doctor:
0 ошибок, **175 предупреждений**, score 42 (Critical); структурные предупреждения
остаются. Эти проверки не заявляются полным аудитом всего продукта.

Полная копия восстановлена изолированно; одна задача очереди повторно завершена
без изменения production. Startup failure и HTTP 503 отрепетированы с возвратом
конфигурации без отката рабочих данных. Монитор проверяет origin, базы, очередь,
импорт, диск и backup; доставка уведомлений ещё не подключена.

## Что ещё требуется для полного запуска

1. Cloudflare-авторизация, проверка маршрутов, staging через Worker и переключение
   публичного Worker с проверкой EN/RU, HTTPS, cookies и старых ресурсов.
2. Подтверждение владельцем email, реальная доставка входа и сверка почтового домена.
3. Выбранные реальные GitHub Releases/Actions packages, credential с минимальными
   правами для Actions и подтверждённые источники/права использования.
4. Получатель аварийных уведомлений и проверка доставки; согласованные участники пилота
   и финальная редакционная проверка контента.
5. Фактические 72 часа автономного staging, проверка длительной нагрузки и 7 дней
   наблюдения после открытия. Новый финальный стенд не выдаётся за уже завершённый прогон.

GitHub ограничивал unauthenticated запросы на staging. Worker сохраняет cooldown,
оставляет задачи в очереди и возобновляет их отдельно от суточного обнаружения.
Git commit/push и удалённый запуск GitHub CI не выполнялись; проверенный пакет
сохранён независимо от несохранённого git-состояния.
