# Каталог и автономный импорт: состояние 2026-10-04

Это исторический отчёт этапа v6. Текущее состояние всех 100 пунктов, последнего
origin-релиза и staging описано в [production-status.md](production-status.md).

На сервере активен `/opt/reporadars/releases/20261004-next-intake-v6`.
Next.js обслуживает страницы через существующий процесс на `127.0.0.1:4320`.
Публичный Cloudflare Worker пока обслуживает прежнюю статическую версию: переключение требует авторизации Cloudflare. Попытка device login завершилась истечением срока кода; Worker, DNS и его маршруты не изменялись.

## Что работает

- Отдельная серверная сборка Next.js: `npm run build:runtime`. Статическая сборка и контракт Sites сохранены.
- Опубликованные скиллы из редакционной SQLite появляются в каталоге, получают EN/RU URL, сохраняются в кабинете. Изменения и архивирование видны без пересборки. Черновики и приватные идентификаторы редакторов не попадают в публичную проекцию.
- Импорт сборников: сканируются все `SKILL.md` в репозитории.
- Импорт готовых ZIP из последнего стабильного GitHub Release: проверяются принадлежность asset, tag, commit, размер, пути, типы файлов, лимиты распаковки, SHA-256 и GitHub digest, когда он указан. Commit тега не выдаётся за доказательство происхождения сборки.
- Очередь кандидатов и события проверки хранятся в отдельной `intake.sqlite`. Публикация получает идемпотентную квитанцию в редакционной базе.
- Раздел «Импорт GitHub» позволяет проверить кандидата, опубликовать или отклонить его, разрешить или отключить автопубликацию для источника.
- Политика `metadata-v1`: автопубликация только для разрешённого источника с подтверждёнными правами, распознанной лицензией, достаточным качеством и без повышенных рисков. Пакет без проверенного GitHub digest требует проверки. Заблокированный кандидат нельзя разрешить кнопкой публикации.
- Новые commit и изменения, конфликтующие с редакторскими правками или архивированием, требуют проверки. Автоматического отката к старому commit нет.
- Фоновая задача `reporadars-intake.timer` включена: ежедневный поиск по GitHub topic `agent-skills`, до пяти репозиториев и трёх ZIP-пакетов за запуск, с ротацией известных источников и результатов поиска. Сканер работает отдельным пользователем, без доступа к auth DB и SMTP; скачанный код не исполняется.
- Задачи имеют ключ версии, lease, повторные попытки и таймауты. Репозитории без `SKILL.md` пропускаются. Опасные и чрезмерно большие архивы получают terminal `blocked` до изменения версии источника. Остальные ошибки сохраняются в приватном журнале задач; повторная попытка отложена на шесть часов и выполняется, когда источник вновь попадёт в бюджет запуска.

Первый запуск обработал три репозитория: 41 кандидат, 37 `needs_review`, 4 `blocked`.
Две задачи завершились ошибкой сканирования. Для одной отдельно подтверждено превышение лимита распаковки; лимит не повышался.
Автопубликация источников по умолчанию отключена: редактор подтверждает источник в админке.

## Развёртывание и проверки

Активация создаёт новый каталог релиза и онлайн-копию SQLite, затем проверяет зависимости от имени пользователя сервиса. После переключения проверяются анонимная сессия и HTML Next.js; при ошибке возвращается прежний релиз и конфигурация nginx, без восстановления старой базы поверх текущей.

Первый пакет исключил нужную зависимость `trace`; он возвращён на предыдущий релиз. Следующая проверка обнаружила закрытые права исходной папки `src`; автоматический возврат сработал. Финальная упаковка нормализует права только публичного кода внутри нового релиза. Приватные данные вне релиза не меняют прав.

Каталог `/var/backups/reporadars` отсутствовал, из-за чего ежедневный backup не работал. Каталог восстановлен; `reporadars-backup.service` теперь завершился с `Result=success`, `ExecMainStatus=0`. В резервные копии включена отдельная intake SQLite через её online backup API.

Проверено:

- 59 Node-тестов API, авторизации, очереди публикации и статического Worker.
- Полный финальный прогон: 69 браузерных тестов прошли.
- Отдельный браузерный тест серверного Next.js: новый slug, переход по ссылке, EN/RU, сохранение, обновление, архивирование, Markdown и фирменная 404.
- Тест фонового обработчика: повторный запуск не отправляет уже обработанную версию; отсутствие `SKILL.md` запоминается; сервисные переменные не передаются сканеру. Опасный архив блокируется, повторный запуск его не скачивает.
- Go `test -race` и `vet`; ZIP-сборники, принадлежность Release asset, digest и запрет опасных редиректов.
- Semgrep выбранных файлов: 0 результатов, 0 ошибок после документирования локального HTTP транспорта между двумя процессами на loopback.
- На origin: `/skills`, `/ru/skills`, `/admin`, `/api/auth/session` — 200; `/404` — фирменная 404; Markdown — 200 с attachment; `/api/admin/intake` без сессии — 401. Проверен HTTPS origin с сохранением имени домена. Публичные `/health`, `/v1`, `/deckview-api/v1/archetypes` сейчас возвращают 404; их прежняя работоспособность не утверждается. Cloudflare Worker не менялся.

Защищённые файлы адаптера Sites не изменены. Git commit/push не выполнялись. Старые релизы, конфигурации возврата и резервные копии сохранены.

## Следующие шаги

1. Авторизовать Cloudflare, проверить аккаунт и владельцев существующих маршрутов. Загрузить версию из `ops/reporadars/wrangler-runtime.jsonc` через `wrangler versions upload`, затем активировать через `versions deploy`, сохранив маршруты и DNS. Проверить все публичные EN/RU страницы, вход, Markdown и прежние origin endpoints.
2. Подтвердить нужные источники в админке после входа владельца по email. Права администратора не подделывались.
3. Уточнить конкретные GitHub сборки. В этой версии поддерживаются ZIP Releases; tar.gz и GitHub Actions artifacts ещё не реализованы. Actions дополнительно требуют доступа GitHub, учёта workflow/run SHA и срока хранения артефакта.
4. Подключить проверенный модельный адаптер и бюджет. Сейчас сохраняется исходное описание с явной отметкой оригинала в RU; автоматическая генерация переводов и Antigravity inference не включались.
5. Следующие части исходного плана: динамические коллекции и статьи, полный журнал фоновых запусков в админке, управление очередью и обновлениями, расширение политики и поиска источников.
